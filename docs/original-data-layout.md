# 原作データ配置規約

原作データは読み取り専用です。実際のファイル名やディレクトリ構造は解析環境のまま保持し、`config/kanon.project.example.json` をコピーしたローカル設定から相対パスで参照します。

推奨例は次のとおりですが、固定仕様ではありません。

```text
private/
  kanon_original/
    kanon.project.local.json
    scenario/
    images/
    bgm/
    se/
    voice/
      0/
      1/
      2/
      ...
      9/
      A/
      B/
        0/
        1/
        ...
cache/
  kanon/
    decoded/
    converted-assets/
    kag-data/
```

規則:

1. `private/kanon_original/` 内をImporterから更新しない。
2. 変換後アセットと中間表現は `cache/kanon/` だけに書く。
3. cacheは削除後に原作データから再生成できるようにする。
4. シナリオ命令が直接指定するファイル名から、論理アセット参照とKAG storage名をImporterが自動生成する。ユーザーがファイル一覧や対応表を手入力する必要はない。
5. 原作本文、画像、音声、変換物をGitへ追加しない。
6. `scenario/`では制御命令を持つ`.org`を必須とし、本文リソースを持つ場合だけ同名の`.utf`を配置する。`.org`単独のシーンは有効だが、`.utf`単独は入力ミスとして扱う。

## アセット形式と解決規則

- 画像はBMP、BGM・SE・VoiceはWAVとして扱う。原作BGMのNWAからWAVへの変換は、元ファイルを上書きせず、再現可能なローカル手順として今後整備する。
- シナリオ側の指定名を原作アセットIDとしてそのまま保持する。
- Importerは命令の種類から検索対象（画像、BGM、SE）を決め、対応ファイルを自動的に解決する。
- 解決した対応関係は `cache/kanon/decoded/` 以下へ生成し、原作側へmanifestを書き込まない。
- 指定ファイルが存在しない場合や、同じ指定名に複数候補がある場合は変換を停止する。推測で別ファイルを選ばない。
- 大文字・小文字を含む実ファイル名と、Voiceのキャラクター別ディレクトリ構造は保持する。

## Voice

Voiceは他の移植用データと同じく `private/kanon_original/voice/` に配置します。

Voice直下にはキャラクター別フォルダ `0`〜`B`（`0`〜`9`、`A`、`B`）があり、その中に各キャラクターのWAVがあります。フォルダIDとファイル名は変更せず、そのまま保持します。フォルダIDとキャラクター名の対応は推測しません。

Voiceだけはシナリオに元から参照が存在しないため、後から「シナリオ位置・フォルダID・WAVファイル名」の手動指示を関連付けます。手動指示は原シナリオを書き換えず、別のローカルデータとして重ねます。

再生はSE系の再生機構を使用します。ただし移植版の状態・トレース・論理アセット種別では通常のSEとVoiceを分け、Voiceの再生中状態を検証できるようにします。

## ローカル配置テスト

原作ファイルを外部へ送らず、次のコマンドで配置とファイルヘッダを検査します。

```console
npm run validate:assets
```

この検査は `scenario/` の存在、`images/` 内のBMP、`bgm/`・`se/`・`voice/` 内のWAV、Voice直下の `0`〜`B`、およびBMP/WAVヘッダを確認します。Voiceの手動指示との対応確認は、指示形式の実装後に別途行います。
