# 実Kanon Decoderに必要な解析情報

原作ファイルそのものは不要です。実Importerの各段階で必要な情報は以下です。

## 1. ファイル境界

- `SEEN.TXT` と制御データの役割分担
- 1ファイル内のヘッダ、索引、データ領域の位置
- レコード境界の求め方
- 数値のendian、符号、bit幅
- 文字列の文字コード、終端、長さ表現
- 圧縮・暗号化・チェックサムの有無

## 2. 命令表

opcodeごとに次を提示します。

```text
opcode:
引数の型と順序:
引数の意味:
実際のゲーム上の挙動:
同期/非同期:
状態への影響:
確認できた原作位置:
不確実な点:
```

opcodeの意味が未確定なら、候補を一つに決めず不明点を残します。

## 3. 制御フロー

- シーン、ラベル、オフセットの参照方式
- jump/call/returnのアドレス基準
- 選択肢の保存形式
- 条件式の演算子、型変換、短絡評価
- 変数・フラグのスコープ、初期値、永続性

## 4. アセット参照

- 原作の背景、立ち絵、CG、BGM、SEの識別子形式
- シナリオが指定するファイル名と、種類別フォルダから実ファイルを解決する規則
- 立ち絵差分の合成方法
- 座標系、基準点、画面サイズ
- レイヤ番号と前後関係
- 対応形式と必要な変換

現在確認済みの原形式は、画像がBMP、BGMがNWA、SEとVoiceがWAVです。現在のローカル配置ではBGMをWAVとして扱いますが、原NWAを上書きせずに同じWAVを再生成できる変換手順は未実装です。NWAについてはKiriKiri側で直接再生できると仮定せず、ヘッダ・圧縮方式・出力形式を確認してから変換処理を実装します。

Voiceは `private/kanon_original/voice/` に配置しますが、元シナリオにVoice参照がないため手動指示として重ねます。実装には次の抽象化済み情報を使用します。

- `KANON_SE/WAV/` 直下のフォルダIDとキャラクターの対応
- 手動指示で使うキャラクターフォルダID（`0`〜`B`）と、その中のWAVファイル名
- Voiceを挿入するシナリオ位置の指定方法
- Voiceを呼び出していたSE系命令名、引数、チャンネル番号
- 次のVoice、SE、場面切替、クリック時に停止または重複再生するか

画像・BGM・SEのファイル名一覧や手書きの対応表は要求しません。Voiceについては再生位置・フォルダID・WAVファイル名を結ぶ手動指示だけを保持し、フォルダIDを推測でキャラクター名へ変換しません。

## 5. タイミングと入力

- waitの単位とスキップ可否
- text送り、既読、オート、スキップの規則
- 音声・SE・BGMの停止待ちとフェード
- transitionの種類、時間、rule、vague相当値
- 入力受付中に進む処理の有無

## 最小の最初の提供単位

全opcode表を一度に揃える必要はありません。最初の実装単位は、抽象化済みの1シーンについて以下があれば成立します。

- 先頭から末尾までのレコード列
- 各レコードのoffset、opcode、生引数の型と値
- 各命令の確定済みの意味
- 参照されるアセットIDと種類の対応
- 原作上で観察した表示・音・入力・時間の順序
